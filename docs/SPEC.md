# SecretAIry 仕様書

架空の美容室のための AI 秘書。AI は「案を出す・仮押さえする」まで。**確定は人のボタンだけ**。

- 版：0.3（カルテ自動作成・朝の要点（並べるだけ）・「前回を見る」をカルテにつなぐ）
- 対象の店：架空の美容室「omochi」（店の情報は `config/` にあり、コードには書かない）
- データはサーバーに保存しない。見ている人のブラウザの中だけに残す（§5.1）

---

## 1. 必須の5つ

| # | 機能 | 一言で | 置き場所 |
|---|------|--------|----------|
| 1 | 予約チャット | お客様と話して空きを探し、**仮押さえ**まで。確定はしない | 予約タブの右の列 |
| 2 | 1週間の予約台帳 | 今日から7日分を1画面で。日ごとに大きい数字（件数）と小さい棒（埋まり具合） | 予約タブの真ん中 |
| 3 | カルテ自動作成 | 施術後のメモからカルテの**案**を作る（Haiku）。言葉の門を通し、人が「保存」を押して記録に入る（§1.5） | カルテタブ |
| 4 | 朝の要点 | 今日の予約数・承認待ち・ToDo を大きい数字で。今日の予約と前回メモ（次回提案）・今日の空き枠を並べる（§1.6）。AI の一言（3つまで）はまだ | ホームの真ん中 |
| 5 | オーナーの承認 | AI の案・仮押さえを1枚ずつ見て押す（予約の仮押さえは「承認」「直す」「見送り」。§1.3） | ホームの右の列（承認の箱）。予約タブの中にも同じ行 |

### 1.1 仮押さえと確定の流れ

```
お客様 ──(予約チャット)──▶ AI
                           │ ルールで確かめる（✓）
                           ▼
                     候補（2つまで）──お客様が選ぶ──▶ 仮押さえ ──▶ 承認の箱（ホーム・予約タブ）
                                         │
                       オーナーが「承認」を押す ─▶ 予約が確定 ─▶ 台帳に入る ─▶ 日誌に記録
                       オーナーが「直す」「見送り」を押す ─▶ 仮押さえを外す ─▶ ToDo に「別の日時を案内」─▶ 日誌に記録
                       だれも押さない ─▶ 期限（config/shop.json の holdExpiresHours）で外れる
```

- 仮押さえの間、その枠は他の人に出さない。
- AI がお客様に返す文は「仮でお取りしました。お店から確定のご連絡をします」まで。「確定しました」とは言わない。
- 確定できるのは、人が押したボタンだけ（§4.5 鍵つきルール）。人のボタンは「画面のボタン」と「オーナー用の合言葉でつないだ LINE のボタン」の2つだけ。

### 1.2 予約チャット（予約タブの右の列）

お客様のスマホの画面のつもりの見た目。お客様（架空）を選んで話す。

- **呼び方**：画面 → `/api/ai/reserve`（Vercel のサーバーの側）→ Claude（モデルは `config/ai.json` の `model`。Sonnet）。道具つきで呼び、返事は1行ずつの JSON で少しずつ流す。
- **送る物**：送るたびに、そのブラウザの台帳（最初の状態＋仮押さえ＋確定＋前回の来店）とルール、話しているお客様のカルテの日付とメニュー（中身は送らない）、「翌日へ」で進めた日数をいっしょに送る。サーバーは何も残さない。ルールはサーバーで鍵つきを先頭に足しなおし、オーナーのルールは `validate.ts` で確かめなおす（送られた物で鍵つきは緩まない）。
- **道具は4つだけ**（`src/lib/ai/tools.ts`）。🔒 確定の道具は作らない。どの道具も答えはプログラム（`slots.ts` → `judge.ts`）が出す。

| 道具 | 画面の名前 | すること |
|---|---|---|
| `find_openings` | 空きを調べる | そのメニューで受けられる枠を、指定の日時から先へ2つまで（店の設定とルールを通った物だけ） |
| `check_rules` | ルールを確かめる | お客様の言った日時を判定。受けられないときは理由1文と、代わりの時間を2つまで |
| `previous_visit` | 前回を見る | そのお客様の、保存したカルテ（最初の状態の「前回までのカルテ」も含む）のうち今日まででいちばん新しい物の日・メニュー・所要時間。無ければ「前回の記録なし」 |
| `place_hold` | 仮押さえ | お客様が直前の候補から選んだときだけ。サーバーでもう一度判定してから仮押さえを返す |

- **受けられないとき**（ルール・定休日・最終受付をまたぐ・埋まっている、どれも同じ）：理由を1文と、代わりの時間を2つまで出す。お客様が「1つ目で」と返すと仮押さえ。
- **仮押さえの守り**：直前にお客様へ出した候補の中からしか押さえない（AI が自分で決めた日時は押さえない）。1回の相談で1つまで。サーバーでもう一度判定し、埋まっていれば押さえずに代わりを出す。
- **上限**（`config/ai.json`）：1回の返事の長さ `maxReplyTokens`、1回の相談で道具を呼ぶ回数 `maxToolCalls`、送る会話の数 `maxMessages`、お客様の1回の文の長さ `maxMessageChars`。道具の上限に来たら止めて「お店に確かめてから、ご連絡します」と返す。
- **AI につながらないとき**（鍵が無い・クレジットが無い・止まっている など）：チャットに「今は AI につながりません」と出す。ほかの画面（台帳・承認の箱・ルール・日誌）はそのまま動く。「決まった返事で試す（AI なし）」を押すと、AI の代わりに決まった返事（`src/lib/ai/script.ts`。テストと同じ物）で、同じ道具・同じ流れを試せる。
- **例文ボタン3つ**：「普通の予約」「ルールで断られる予約」「前と同じで」。日時はいまの台帳・ルール・時刻からプログラムが選んで文を作る（どの曜日・時刻に開いても、普通の予約は受けられる日時、断られる予約はルールで断られる日時になる。ルールで断られる枠がその時に無いときだけ、最終受付を過ぎる日時にする）。「前と同じで」は、前回のカルテがあるお客様で話し、カルテのメニューで所要時間とルールを判定して候補を出す。
- **AI の手順**（予約タブの真ん中）：相談ごとに、どの道具で何を調べ、どのルール（または店の設定）で外したかを日本語で1行ずつ。同じ行を日誌にも書く。

### 1.3 承認の箱

- ホームの右の列と、予約タブの中に同じ行を出す。1行に「何を（お客様・メニュー）・いつ・理由（1文）」と、いまの台帳とルールで受けられるか（✓ / ✗）。
- ボタンは「承認」「直す」「見送り」。押すとプログラムが実行する（AI は使わない）。
  - **承認**：確定して台帳に入る。
  - **直す・見送り**：お客様の了解なしに時間は変えないので、仮押さえを外し、日誌に一言残し、ToDo に「○○（架空）様に別の日時を案内」を足す。
- 確定は、人が画面のボタンを押したときだけ（ブラウザの本物の操作か `isTrusted` で確かめる）。サーバー・AI・自動の処理には確定の入口が無い。
- 台帳では、仮押さえ（点線・しま模様）と確定（実線）を色で分ける。

### 1.4 予約サイト（架空）

- 予約タブで、台帳の横に並べる。お客様が見る空き状況のつもり（○ 空き・△ のこりわずか・× 満席）。
- 今は台帳 → 予約サイトの片方向だけ。台帳で確定した予約を受け取り、その枠を塞ぐ（承認で確定した予約の入った枠は太枠）。仮押さえは送らない。

### 1.5 カルテ自動作成（カルテタブ）

- **真ん中**：今日の予約（確定）のお客様（架空）を並べ、先頭を最初から選んでおく。選んだ方の「今日のカルテ」（案・保存済み）と「前回までのカルテ」。
- **右の列**：施術後のメモ（1,500字まで。`config/ai.json` の `karte.maxMemoChars`）。字数を「n/1500字」で出し、空か超えたときは「カルテにする」を押せない。スマホのキーボードの音声入力で入れる前提で、録音の機能は作らない。
- **例文を入れる**：今日（最初の状態の0番目の営業日）のお客様1人に1つ、話し言葉の例文（`seed/karte-examples.json`）。1つには「頭皮が赤かった」が入っている。例文の無い方ではボタンを押せない。
- **カルテにする**：画面 → `/api/ai/karte` → Claude（`config/ai.json` の `karte.model`。Haiku）。送るのはメモとルールだけ（お客様の名前は送らない）。サーバーは何も残さない。
  - 見出しは `config/karte.json` の8つ：来店時の状態／お客様のご希望／施術内容／薬剤・設定／仕上がり／次回提案／注意点・申し送り／会話メモ。
  - AI は見出しごとに「■ 見出し」、その下に「・」の短い行で書く。メモに無い見出しは空のまま（画面では「メモに無し」）。メモに無いことは足さない。プログラム（`src/lib/karte/format.ts`）が見出しごとに分け、知らない見出し・見出しの外の行は使わない。
  - カルテのお客様の名前・日付・メニューは、選んだ予約からプログラムが入れる（Claude には書かせない）。
  - 1回の返事の長さに上限（`karte.maxReplyTokens`）。上限で切れたら最後の1行は使わず「途中までの案です」と出す。
- **言葉の門**（プログラム。`src/lib/karte/gate.ts`）：下書きを1行ずつ見て、頭皮・肌・病・受診・薬・おすすめ・改善などの言葉（`src/lib/rules/locked.ts` の `KARTE_GATE_WORDS`）や数字がメモに無ければ、その1行だけ外し、「1行を載せていません（理由）」と出して日誌にも書く。メモにある言葉（例：「頭皮が赤かった」）は記録として残す。頭皮や肌の判断・助言はしない（🔒 鍵つきの2つ目）。保存の直前にもう一度通す。
- **案のカード**：大きいカード1枚。「前（施術のメモ）→ 後（カルテ）」と理由1文。ボタンは「保存」「やめる」。
- **保存**（人のボタン。`isTrusted` で確かめる）：そのお客様の記録に入る（`secretairy:book` の `kartes`）。「次回提案」の1行目を ToDo の「次回話すこと」に1件だけ足す（2行目からは「（ほかN行はカルテに）」と添える。まだ済んでいない同じ題の物があれば足さない）。日誌に「人が保存」。保存したメモは、その日はもう直さない（同じ方・同じ日の2回目の保存はしない）。
- **前回までのカルテ**：そのお客様の保存済みカルテを新しい順に並べる（AI なし）。最初の状態に、架空のお客様の前回までのカルテ（8見出し。`seed/kartes.json`）を入れてある。日付・メニューは予約の「前回」（`seed/reservations.json` の負の数の日）から取るので、いつもそろう。
- **AI につながらないとき**：「今は AI につながりません」と出し、ほかの画面はそのまま動く。「決まった返事で試す（AI なし）」で、AI の代わりに決まった返事（`src/lib/karte/writer.ts` の `scriptKarteWriter`。テストと同じ物）で同じ流れ（見出しに分ける → 言葉の門）を試せる。例文のメモには決まった下書き（AI の書きすぎを1行まぜた物もある）、ほかのメモは見出しの手がかりの言葉（`config/karte.json` の `hints`）で文を分ける。

### 1.6 朝の要点（ホームの真ん中。並べるだけ）

- 大きい数字：今日の予約・承認待ち・今日の ToDo。
- 今日の予約（時刻・メニュー・お客様）と、そのお客様の前回メモ（今日より前でいちばん新しいカルテの「次回提案」）。無ければ「前回の記録なし」。
- 今日の空き枠（これから）：台帳（確定・仮押さえ）と席の数から、30分ごとの空きの席をまとめて出す（プログラム ✓）。ルールで受けられるかは予約チャットで確かめる。
- **翌日へ**（デモ用）：今日を1営業日先へ（定休日は飛ばす）。進めた日は「開店1時間前」をいまの時刻にする。台帳・カルテ・予約チャットも同じ「今日」で動く（サーバーにも進めた日数を送る。`calendar.ts` の `demoClock`）。「最初に戻す」で本当の今日に戻る。
- AI の文章（気をつける点を3つまで）はまだ（§9.3）。

### 1.7 広告の見直し（広告タブ）

架空の広告の4週分を見て、AI が「止める言葉」か「外す言葉」を1つ提案し、承認の箱でオーナーが決める。

```
「AI に見直してもらう」（右の列）──▶ /api/ai/ads ──▶ Claude（Sonnet）が案を1つ（止める / 外す）
                                         │ プログラムの門（✓ 3つ）
                                         ├─ 弾いた ─▶ 理由を渡して1回だけ作り直す ─▶ それでもだめなら案は出さず、日誌に書く
                                         ▼
                                   承認の箱（ホーム・広告タブ）
   承認 ─▶ 広告（架空）の画面でその言葉が止まる（外れる）・一覧の行を薄く・ToDo「3週間後に効いたか見る（N番）」（期限つき）・日誌
   直す ─▶ 一言（例「3番を止めて」）で AI が1回だけ出しなおし ─▶ もう一度門を通す（通らなければ前の案のまま）。2回目は受けない
   見送り ─▶ 案を閉じて日誌に1行
```

- **数**：`seed/ads.json` に4週分（4週前・3週前・2週前・先週）。「広告を出す言葉」8つ（1〜8番。止められる）と、「お客さんが調べた言葉」の多い順8つ（9〜16番。外せる）。1つずつに番号・押された回数・かかったお金・予約の数を週ごとに。番号は2つの一覧を通して1つずつ違う。売りのメニュー（`config/ads.json` の `featuredMenus`）の言葉には「売り」の印。
- **画面**：上に大きい数字3つ（押された回数・かかったお金・予約。広告を出す言葉の4週の合計）と、週ごとの小さい縦棒（`MiniColumns`）。その下に「広告（架空）の画面」と2つの一覧。止めた・外した行は薄くする。
- **町の名前**：架空の町の名前の一覧は `config/ads.json` の `towns`。調べた言葉の中に、町の名前入りの言葉を1つ混ぜてある（9番）。
- **道具は2つだけ**（`src/lib/ads/tools.ts`）：`stop_keyword`（止める）・`exclude_term`（外す）。どちらも番号と理由1文しか受け取らない。言葉を足す道具は作らない（売りのメニュー以外へ広げない）。道具を呼んでも何も変わらない。
- **数は AI に書かせない**：回数・お金・予約は、表からプログラムが入れる。AI への表の文もプログラムが書く（`report.ts` の `tableText`）。理由の文に数字があれば門で弾く。
- **プログラムの門**（`src/lib/ads/gate.ts`。画面では「プログラムの確認」として ✓ を3つ）：
  1. 番号が表にあるか（止める＝広告を出す言葉・外す＝調べた言葉。もう止めた物は選ばない）
  2. 言葉を足していないか（止める・外す以外の道具、番号と理由のほかに付けた物は弾く）
  3. 外す言葉に町の名前が入っていないか（町の名前は外さない）
  - ほかに形も見る：案は1回に1つ・理由は1文で数字なし。
  - 画面でも、受け取った案をもう一度同じ門で確かめてから承認の箱に入れる。
- **1週間に1つまで**（`config/ads.json` の `oncePerDays`）。承認待ちの案があるときは新しく出さない。承認・見送りのどちらも1つと数える。門を通らなかった時は数えない。
- **承認**：人が画面の「承認」を押したときだけ（`isTrusted`）。ToDo の期限は承認した日から `checkAfterDays`（21日）後。お休みの日なら次の営業日。
- **上限**：1回の返事の長さ `config/ai.json` の `ads.maxReplyTokens`（600）。道具は1回に1つ（`disable_parallel_tool_use`）。
- **AI につながらないとき**：右の列（と「直す」）に「今は AI につながりません」と出す。「決まった返事で試す（AI なし）」で、決まった返事（`src/lib/ads/script.ts`。テストと同じ物）が同じ門・同じ流れを通る。決まった返事は町の名前を知らないので、1回目は9番を外す案を出し、門に弾かれて作り直す（門の働きを見られる）。
- **ブラウザの中の置き場所**：`secretairy:ads`（広告の案・止めた／外した言葉）。ToDo は `secretairy:book` の足した ToDo に入る（id は `td-ad-`）。右の列の「広告（架空）を最初に戻す」で、広告の案・止めた言葉・広告から足した ToDo を消す（日誌には残す）。

## 2. タブ（8つ）

| タブ | パス | 必須にかかわる | 真ん中 | 右の列 |
|------|------|:---:|--------|--------|
| ホーム | `/home` | ○ | 朝の要点 | **承認の箱** と **日誌** |
| 予約 | `/reservations` | ○ | 1週間の予約台帳 | 予約チャット |
| カルテ | `/karte` | ○ | 今日のお客様・カルテの案・前回までのカルテ | 施術後のメモの入力 |
| 広告 | `/ads` | | 広告の4週分・広告（架空）の画面・承認待ちの行（§1.7） | AI に見直してもらう |
| 経理 | `/accounting` | | 売上・使ったお金 | お金の出入りの入力 |
| ToDo | `/todo` | | やることの一覧 | やることを足す入力 |
| 発信 | `/posts` | | SNS などの文の案 | 発信のお題の入力 |
| ルール | `/rules` | ○ | 3段のルール一覧 | ルールを足す入力 |

### 2.1 表示スイッチ

- タブごとに出す・隠すを `config/tabs.json` の `visible` で持つ（最初の状態）。
- 各タブの見出しの横にスイッチを出す。画面で切りかえた分は見ている人のブラウザの中だけに残す。隠したタブは左のタブの下の「隠しているタブ」から開いて、スイッチで出しなおせる。
- 間に合わないタブは `visible: false` にすれば、左のタブから消え、URL を直接開いても「出していません」になる。
- 必須にかかわるタブ（ホーム・予約・カルテ・ルール）は、スイッチを切っても隠れない。
- 並び・名前・印はタブの仕組みの側（`src/lib/tabs.ts`）で決める。店ごとに変えるのは出す・隠すだけ。

### 2.2 承認待ちの1行

- どのタブでも、ページのいちばん上に「承認待ち **N** 件 →」を1行出す（数はそのブラウザの承認待ち）。
- 押すとホームの承認の箱（`/home#approvals`）へ行く。
- 1件以上あるときは色を変えて目立たせる。

## 3. 画面の形

### 3.1 PC（横幅 1024px 以上）：3列

```
┌──────────┬──────────────────────────────┬──────────────┐
│ 左：タブ │ 真ん中：ページ               │ 右の列       │
│ 🏠ホーム │ [承認待ち N件 →]             │ ホーム：     │
│ 📅予約   │ 見出し                       │  承認の箱    │
│ 📋カルテ │ 中身                         │  日誌        │
│ …        │                              │ ほかのタブ： │
│          │                              │  そのタブの  │
│          │                              │  入力欄      │
└──────────┴──────────────────────────────┴──────────────┘
```

- 左のタブは「«」で畳める（印だけになる）。
- 真ん中と右の列の境目はつまんで動かせる（矢印キーでも。2回押すと元の幅）。
- 畳んだか・右の列の幅は、そのブラウザの中だけに覚えておく。

### 3.2 スマホ：1列

上から「タブ（横に流せる）→ 承認待ち N件 → ページ → 右の列だった物」の順。横にはみ出さない。

### 3.3 読みやすさの決まり

慣れていない人でも読めるように：

- **数字は文字より大きく。** 件数・金額は大きい数字で見せる（`BigNumber`）。
- **量は小さい棒で。** 埋まり具合・割合は細い横棒（`MiniBar`）。
- **プログラムが確かめたことは ✓ の印。** AI の言葉と区別する（`Checked`）。
- **AI の案は大きいカード1枚。** 中身は「前 → 後」と「理由1文」だけ。ボタンは「確定」「やめる」（予約の仮押さえの行だけは「承認」「直す」「見送り」。§1.3）。
- **細かい所は畳む。** 「くわしく」を押したら開く（`Fold`）。
- **むずかしい言葉は言い換える。** 下の表のとおり。

| 使わない言葉 | 使う言葉 |
|---|---|
| ステータス | 状態 |
| ペンディング / 保留 | 承認待ち |
| リザーブ / ホールド | 仮押さえ |
| コンファーム | 確定 |
| キャンセル（店側の操作） | やめる |
| ログ / 履歴 | 日誌 |
| スコープ | どこに効くか |
| バリデーション | 確かめる |
| エラー | うまくいきませんでした（＋どうすればよいか1文） |
| ダッシュボード | ホーム |

## 4. ルール

### 4.1 考え方

- 店の決まりは店ごとに違うので、**作り手は決めて書き込まない。**
- オーナーがルールのタブから **足す・直す・消す**。足したルールは**次の判定からすぐ効く**（作り直し・再起動なし）。
- 最初は架空の店の例のルールを数個だけ入れておく（`config/rules.seed.json`）。

### 4.2 3段と札

| 段 | 札の例 | 効く場面 |
|---|---|---|
| 全体 | 「全体」 | どのタブ・どのメニューでも |
| タブごと | 「タブ：予約」 | そのタブの判定のときだけ |
| メニューごと | 「メニュー：カラー」 | そのメニューを含む予約のときだけ。組み合わせのメニュー（例：カット＋カラー）にも効く |

どのルールにも「どこに効くか」の札を必ず付けて画面に出す。

- 組み合わせのメニューは `config/menus.json` の `includes` に中身を書く（例：カット＋カラーは `["cut", "color"]`）。「メニュー：カラー」のルールはカット＋カラーの予約にも効く（`strictest.ts` の `expandMenuIds`）。

### 4.3 ルールの種類

| 種類 | 画面の名前 | 例 | 確かめ方 | 厳しい方 |
|---|---|---|---|---|
| `minLeadMinutes` | 何分前まで | 来店の3時間前まで | プログラム（✓） | 大きい方 |
| `maxNewCustomersPerDay` | 1日の上限（初めての方） | 初めての方は1日4人まで | プログラム（✓） | 小さい方 |
| `bufferAfterMinutes` | 間を空ける | カラーの後は15分あける | プログラム（✓） | 大きい方 |
| `noSameDay` | 同じ日に不可 | 来店と同じ日の予約は受けない | プログラム（✓） | 1つでもあれば効く |
| `lastStart` | 最終受付 | 最終受付は18:00 | プログラム（✓） | 早い方 |
| `text` | 文（AI が読む） | お客様の顔が分かる写真は載せない | AI が読む（✓ は出ない） | ぜんぶ使う |

- プログラムで確かめられる種類は少しずつ足す。足すときは「数が大きい方が厳しいか、小さい方が厳しいか」を必ず決める（`src/lib/rules/types.ts` の `STRICTER`）。あわせて `src/lib/rules/judge.ts` に確かめ方を、`src/lib/rules/__tests__/judge.test.ts` に「通る例」と「断る例」を足す。
- 型に入らない文は、Claude への指示に入れる（`src/lib/rules/prompt.ts`）。AI の答えは承認の箱を通るので、最後は人が見る。
- 「間を空ける」は、その予約の後ろに間を足して席を数える。新しい予約の側のルールだけでなく、すでに入っている予約の側のルール（例：前のカラーの後の15分）も効く。
- 「最終受付」のルールは、メニューの設定の最終受付（`config/menus.json` の `lastStart`）とは別に効く。どちらも確かめる。架空の店の最終受付はメニューの設定で持ち、例のルールには入れない（設定が判定に効くことは `seed.test.ts` で確かめる）。
- 「同じ日に不可」も例のルールには入れない（オーナーが画面から足す）。

### 4.3.1 判定はプログラム、AI は従うだけ

- 予約を受けてよいかは `src/lib/rules/judge.ts` が決める。ルールは必ず `strictest.ts` を通し、その場面で効く厳しい方の1つで確かめる。あわせて店の設定（営業日・営業時間・メニューの最終受付・席）も確かめる。
- AI への指示には、判定の結果（✓ / ✗ と理由）をそのまま入れ、「変えない・従う。受けられないときは仮押さえをしない」と書く。
- ルールのタブの右の列「ためしに確かめる」で、いまのルールでの判定を見られる。ルールを足す・直す・消すと、結果もすぐ変わる。

### 4.3.2 足す・直す・消す

- 足す形は「種類を選ぶ → どこに効くか（全体・タブ・メニュー）を選ぶ → 数を入れる」。型のルールの文は、種類と数から作る（数を直すと文も変わる）。
- 型のルールは予約の判定で使うので、タブは「予約」だけに付けられる。文のルールはどのタブにも付けられる。
- 言葉で書いて型のルールにする（AI に読み取らせる）のは後で足す。
- 足した・直した・消した分は、見ている人のブラウザの中だけに残す（`secretairy:rules`）。読むときも同じ確かめ方を通すので、ブラウザの中を書きかえても鍵つきは緩まない。

### 4.3.3 テスト

```bash
npm test
```

- 種類ごとに「通る例」と「断る例」（`src/lib/rules/__tests__/judge.test.ts`）。
- 架空の店の例のルールに1本ずつ（`src/lib/rules/__tests__/seed.test.ts`）。例のルールを足してテストを足し忘れると、テストが落ちる。メニューの設定の最終受付が判定に効くことも、ここでメニューごとに確かめる。
- ぶつかったら厳しい方（`strictest.test.ts`）、鍵つきの2つ（`locked.test.ts`）。

### 4.4 ぶつかったら厳しい方

1. その場面（タブ・メニュー）に効くルールを3段すべてから集める。
2. 同じ種類の数のルールが2つ以上あれば、**厳しい方の1つ**を使う。段の上下では決めない。
   - 例：全体「3時間前まで」と メニュー：縮毛矯正「24時間前まで」→ 縮毛矯正の予約では「24時間前まで」。
3. 文のルールはぜんぶ使う。文どうしがぶつかって決められないときは、AI は進めずに承認の箱へ回す。

実装：`src/lib/rules/strictest.ts`

### 4.5 鍵つきの2つ

| ルール | 守り方 |
|---|---|
| 🔒 **確定は人** — 予約などの確定は人がボタンを押したときだけ。AI は仮押さえまで | AI に「確定」の道具を渡さない。確定の処理は「画面のボタン」と「オーナー用の合言葉でつないだ LINE のボタン」からの呼び出しだけ受け付ける。それ以外（合言葉でつないでいない LINE・AI・自動の処理）は人の承認にしない |
| 🔒 **健康や医療の判断はしない** — 頭皮・アレルギー・妊娠・薬などで「大丈夫」「やめた方がいい」を言わない | AI はお客様の言葉をそのままカルテの「お客様が話したこと」に書き、スタッフにつなぐ。AI への指示の先頭に必ず入れる |

- この2つは仕組みの約束なので `config/` ではなくコード（`src/lib/rules/locked.ts`）に書く。
- 画面では 🔒 を付けていちばん上に出す。消す・直すボタンは出さない。
- オーナーが足すルールで緩めることはできない。足すときに「確定を AI に任せる」「〜なら施術して大丈夫と答える」のような中身なら、受け付けずに理由を1文で返す。（`src/lib/rules/validate.ts` の `lockedConflict`。言葉の組み合わせで見るので、すべては見分けられない。AI への指示でも鍵つきを先頭に置き、最後は承認の箱で人が見る）
- AI への指示では、鍵つき → オーナーのルール の順に並べ、「鍵つきとぶつかったら鍵つきを守る」と書く。

## 5. 設定として持つ物

店ごとに変わる物はコードに書き込まない。今は `config/*.json`、読むのは `src/lib/settings.ts` を通す。

| ファイル | 中身 | 画面から変える |
|---|---|---|
| `config/shop.json` | 店名・時間帯・席数・枠の長さ・仮押さえの期限・営業時間・休みの日 | 後で画面を足す |
| `config/menus.json` | メニュー（名前・時間・値段・最終受付・組み合わせの中身 `includes`） | 後で画面を足す |
| `config/ai.json` | AI のモデル名・1回の返事の長さ・道具を呼ぶ回数などの上限（モデル名は `ANTHROPIC_MODEL` でも差しかえられる）。カルテ（`karte`）のモデル・返事の長さ・メモの字数（モデル名は `ANTHROPIC_KARTE_MODEL`）。広告の見直し（`ads`）の返事の長さ | 後で画面を足す |
| `config/ads.json` | 広告の札（どこの広告か）・売りのメニュー・架空の町の名前・「効いたか見る」までの日数・案を何日に1つまでか | 後で画面を足す |
| `config/karte.json` | カルテの見出し（8つ）。次回提案に `role: "next"`、決まった返事の手がかり `hints` | 後で画面を足す |
| `config/tabs.json` | タブの表示スイッチ | 後で画面を足す |
| `config/rules.seed.json` | 例のルール（最初だけ使う） | **ルールのタブで変える** |

- ほかの画面から読むときも、`config/` を直接 import せず `src/lib/settings.ts` の関数を使う。画面から変えられるようにするときは、その関数の中身だけを差しかえる。
- 最終受付（`lastStart`）は「この時刻までに始める」。書いていないメニューは「閉店 − 所要時間」まで。

### 5.0 架空のデータの最初の状態（`seed/`）

店の設定ではない「お客様・予約・広告・お金・やること」の最初の状態は `seed/` に置く。読むのは `src/lib/data/seed.ts` を通す（画面のコードで `seed/` を直接 import しない）。

| ファイル | 中身 |
|---|---|
| `seed/customers.json` | 架空のお客様10人（名字だけ。画面では必ず「架空」の札を出す） |
| `seed/reservations.json` | 今日から2週間分の予約（今日は3件）と、前回の来店（負の数の日。「前と同じで」に使う） |
| `seed/ads.json` | 架空の広告の4週分（広告を出す言葉8つ・お客さんが調べた言葉8つ。週ごとの押された回数・お金・予約）（§1.7） |
| `seed/accounting.json` | お金の出入り（形だけ。中身は後日） |
| `seed/todo.json` | やること（形だけ。中身は後日） |
| `seed/kartes.json` | 前回までのカルテ（8見出し）。どの予約（前回の来店）の物かだけ持ち、日付・メニュー・お客様は予約から取る |
| `seed/karte-examples.json` | カルテの「例文を入れる」（今日のお客様1人に1つ）と、その決まった返事の下書き |

- 日付は「今日から何番目の営業日か」（0 = 今日）と時刻で持つ。いつ開いても今日から2週間分になり、定休日には置かれない。
- 「今日」は店の時間帯で開いた日。開いた日がお休み（定休日・休みの日）なら、次の営業日を今日にする（画面にその旨を1行出す）。
- 形は `src/lib/data/types.ts`。

### 5.1 データの置き場所（サーバーには保存しない）

- **最初の状態**はリポジトリのファイル（`config/` など）に置く。
- **画面で触った後の変化**（予約・仮押さえ・保存したカルテ・承認・日誌・オーナーが足した／直した／消したルール・設定の変更）は、**見ている人のブラウザの中だけ**に残す。
- サーバーにはデータを書き込まない（`data/` のような置き場所は作らない）。公開 URL を見た人どうしでデータが混ざらないようにするため。
- 読むときは「リポジトリの最初の状態」に「そのブラウザに残っている変化」を重ねて使う。
- ルールの判定もそのブラウザのルールで行う。足したルールがすぐ効くのはこのため。
- AI を呼ぶとき（Claude API の鍵はサーバー側にあるため、サーバーを通る）は、判定に要るデータとルールをブラウザから毎回いっしょに送る。サーバーは答えを返すだけで、送られたデータを残さない。
- 別のブラウザ・別の端末では、データは引きつがれない。ブラウザのデータを消すと最初の状態に戻る。
- **起点の日**：予約の変化をブラウザに残すときは、そのブラウザで初めて開いた日を起点として覚える（`secretairy:book` の `anchor`）。最初の状態の予約（何番目の営業日）はこの日から数えて置く。仮押さえ・確定は本当の日付で残す。台帳・ホームの「最初に戻す」を押すと、本当の今日を起点に作り直す（仮押さえ・承認の箱・足した ToDo・保存したカルテ・「翌日へ」も消える。日誌には残す）。（広告の `secretairy:ads` は消さない。広告タブの「広告（架空）を最初に戻す」で消す）
- ブラウザの中の置き場所：`secretairy:book`（起点・予約チャットからの予約・承認の箱・足した ToDo・保存したカルテ・「翌日へ」で進めた日数）、`secretairy:journal`（日誌）、`secretairy:rules`（ルールの変更）、`secretairy:ads`（広告の案・止めた／外した言葉。§1.7）。読むときはどれも形を確かめる。

## 6. AI

- Claude API を使う。鍵は `.env.local` の `ANTHROPIC_API_KEY`（`.env` で始まるファイルはコミットしない。Vercel では環境変数に入れる）。モデル名も設定で持つ（`config/ai.json`）。
- AI を呼ぶ窓口は `src/app/api/ai/` の下に置く（予約チャットの `/api/ai/reserve`、カルテの `/api/ai/karte`、広告の見直しの `/api/ai/ads`）。
- 安全のために断られたときは、サーバーの側で別のモデルに答えなおさせる（`fallbacks: "default"`。予約チャット・広告の見直し）。カルテの Haiku にはこの仕組みが無いので、断られたら「AI がこのメモをカルテにできませんでした」と出し、決まった返事で試せるようにする。
- AI がしてよいこと：会話・空きの提案・仮押さえ・カルテの案・朝の一言・広告や発信の文の案。
- AI がしてはいけないこと：確定・お金の記録の確定・外への発信・健康や医療の判断。
- AI の出した物は、すべて承認の箱か日誌に残す。
- 数（件数・金額・空き）はプログラムが出す。AI は数を作らない・変えない。

## 7. 日誌

- AI がしたこと（道具を呼んだ・仮押さえ・カルテの案を作った）、プログラムがしたこと（ルールや店の設定で弾いた・上限で止めた・言葉の門で1行を載せなかった）、人が押したボタン（承認・直す・見送り・カルテを保存・カルテの案をやめた・翌日へ・最初に戻す・ルールを足した／直した／消した／例に戻した）を新しい順に並べる。
- 1行に「いつ・だれ（AI / オーナー / プログラム / LINE）・何を」。ホームの右の列に出す。
- 日誌もそのブラウザの中だけに残す（新しい方から300行まで）。

## 8. 後で足す：LINE（今は作らない）

- オーナーの入口として LINE を足す。
- 窓口は `/api/line` に分ける（画面の処理と混ぜない）。
- LINE は**画面が開いている間だけ**動く。常に動くサーバーは前提にしない。
- LINE から来た物も、今と同じ承認の箱・日誌を通す。
- **人のボタンとして扱うのは、オーナー用の合言葉でつないだ LINE から押した物だけ。** それ以外の LINE から来た物は、人の承認にしない。
- 合言葉そのものはリポジトリに書かない。

## 9. 決めたこと・まだ決めていないこと

### 9.1 決まったこと

| こと | 決まった中身 |
|---|---|
| データの保存 | サーバーには保存しない。最初の状態はリポジトリのファイル（`config/` など）、画面で触った後の変化は見ている人のブラウザの中だけに残す。`data/` に書き込む作りはしない。公開 URL を見た人どうしでデータが混ざらないようにするため（§5.1） |
| LINE のボタン | オーナー用の合言葉でつないだ LINE から押した物だけを「人のボタン」として扱う。それ以外は人の承認にしない。LINE の窓口（`/api/line`）は後で作る（§8） |
| お客様向けの予約チャット | 別のページにはせず、予約タブの右の列に置く |
| 架空の店の名前 | 「omochi」 |
| 架空の店の時間 | 火曜定休・開店 10:00。最終受付はカット 19:00・カラー 18:00・縮毛矯正 16:00 |
| 組み合わせのメニュー | メニューごとのルールは、そのメニューを含む組み合わせのメニュー（例：カット＋カラー）にも効く |
| 起点の日 | 予約の変化は、そのブラウザで初めて開いた日を起点に覚える。「最初に戻す」で今日を起点に作り直す |
| 予約チャットのモデル | Sonnet（`config/ai.json`） |
| カルテのモデル | Haiku（`config/ai.json` の `karte`） |

### 9.1.1 仮決め（あとで見直す）

| こと | 仮の中身 |
|---|---|
| 閉店の時刻 | 20:00（カットの最終受付 19:00 ＋ 60分） |
| ほかのメニューの最終受付 | カット＋カラー 18:00（カラーに合わせる）・パーマ 17:00・ヘッドスパ 19:00 |
| 架空のデータの置き場所 | `seed/`（店の設定の `config/` とは分ける） |
| 表示スイッチ・左のタブを畳む・右の列の幅 | 画面で変えた分はそのブラウザの中だけに残す |
| 決まった返事（AI なし） | 予約チャットで「AI（Claude）」と「決まった返事（AI なし）」を切りかえられる。決まった返事はテストと同じ物で、決まった形の文（例文・「1つ目で」など）だけ読む |
| 上限の数 | 1回の返事 1500 トークン・1回の相談で道具 6 回・会話 20 件・お客様の文 300 字（`config/ai.json`） |
| 候補の数 | 2つまで。代わりは頼まれた日時から先へ、14日の中で探す |
